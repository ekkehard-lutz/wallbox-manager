## OCPP connection and observation lifecycle

1. Entry setup loads current profiles and session data, creates one State, Grid, battery owner and PV runtime, restores the current PV journal, starts the OCPP listener and forwards platforms. A restored session initially has no live generation. The current profile configuration, draft and approval survive restart. Manager release and its active NETZ schedule are retired on reload rather than restored as physical authority. [Entry setup](../../custom_components/wallbox_manager/__init__.py#L37) · [Settings recovery](../../custom_components/wallbox_manager/settings.py#L144) · [Session load](../../custom_components/wallbox_manager/session.py#L279)
2. The listener accepts only the bound station path with `ocpp2.1`. It replaces the previous adapter under a lock and allocates a new connection generation. Boot increments the boot generation, fences intents, clears writable inventory and runs one bootstrap after the response. Registration is established by Boot, separately from discovery and field availability. Station identity is routing under F2. [Listener](../../custom_components/wallbox_manager/ocpp.py#L99) · [Boot and bootstrap](../../custom_components/wallbox_manager/ocpp.py#L299)
3. Disconnect makes the generation unavailable. Boot and replacement invalidate old results and observations. Canonical values use generation, source timestamp and scope. Old samples may remain historical. Invalid phase handling follows WBM-ARCH-07, including an authoritative explicit Delta unknown. Silence alone leaves a valid same-generation value held. [Canonical store](../../custom_components/wallbox_manager/store.py#L74) · [Observation ordering](../../custom_components/wallbox_manager/store.py#L111)
4. Adapters own serialized OCPP calls, their shielded response consumers, bootstrap and the permission poll. Close fences command ownership, closes the WebSocket, then cancels and joins the owned tasks. A CALL timeout is an operation failure. Ping timeout or socket closure terminates the transport and invalidates live observations. [Adapter request and close](../../custom_components/wallbox_manager/ocpp.py#L187) · [Transport tests](../../tests/test_protocol.py#L682)
5. Grid's epoch, adapter and transaction guards apply at the wire and on result consumption. Control has its own exact variable and authority-intent guards. For SetChargingProfile, requested current and ACK are separate from a matching accepted composite schedule and compatible phase observation. Actual EV consumption is separate meter evidence. Ambiguous rejection leaves uncertainty, while only the two recognized atomic lockouts can retain the earlier point as certain. A failed read leaves the result unconfirmed. A replacement generation cannot inherit a newly confirmed offer from an older response. [Control fences](../../custom_components/wallbox_manager/control.py#L106) · [Grid fences and readback](../../custom_components/wallbox_manager/grid.py#L953) · [F1 tests](../../tests/test_ocpp_rejection_certainty.py)

## NETZ recovery

- **Existing tests and temporary replay.** The absolute schedule is independent of an eligible socket or EV. In a replay with planned start at 1060, a reconnect at 1090 applied the current approved point with the original end at 1240. Explicit Stop during the same outage retired the request and suppressed a positive proposal on resume. ## Findings and release disposition

### R1 · P1 · NETZ can resend a confirmed target on same-transaction resume without readback

**Confirmed defect and stable blocker.** WBM-GRID-13 and WBM-ARCH-04/10/11 require reconnect reconciliation before any unconditional replay of the unchanged confirmed target. On a generation change, Grid clears `known_transaction`. The first resumed identity then looks new, sets `allow_issue` from the still-active release, and bypasses the missing-point return in `reconcile()`. The pre-wire gates still require the actual registered adapter, Remote, transaction, hardware permission, release and active business window. The issue is replay eligibility, and the later ACK is still unconfirmed. [Generation and transaction handling](../../custom_components/wallbox_manager/grid.py#L837) · [Missing readback branch](../../custom_components/wallbox_manager/grid.py#L1293)

**Evidence.** Confirm 3p/16 A and leave the approved NETZ window active. Reconnect the same station and send a newer scoped `Updated/TxResumed` for the same transaction ID. With failed composite readback, one 3p/16 A write appears on the new socket, and applied current stays unavailable. The matching and valid-mismatch control cases produce zero and one write respectively. This is specific to NETZ automatic recovery. PV remains tick-driven.

**Correction required.** Preserve the distinction between a previously seen resumed transaction and a genuinely new eligible decision in existing Grid context. Keep the old command epoch invalid and leave an unconfirmed same-transaction resume deferred when the existing reconciliation read supplies no point. Keep normal valid-mismatch correction, fresh explicit actions and independently matured business starts. Add a same-ID reconnect/Boot regression matrix for matching, mismatching, rejected and malformed readback, plus a new-ID and offline-start control. Use the existing reconciliation path without a hardware gate or new read loop.

### R2 · P1 · PV journal failure aborts teardown before closing the listener

**Confirmed defect and stable blocker.** WBM-CTRL-10 and WBM-ARCH-11/12 require teardown ownership and no old live controller after runtime replacement. Unload removes the platforms and awaits `PV.close()` before Grid, battery and server shutdown. Its final persistence can raise. HA Stop and listener/setup error cleanup use the same vulnerable ordering. [HA Stop and unload](../../custom_components/wallbox_manager/__init__.py#L113) · [Setup cleanup](../../custom_components/wallbox_manager/__init__.py#L77) · [Final PV persistence](../../custom_components/wallbox_manager/pv.py#L947)

**Evidence.** With a registered simulated peer and changed current-format budget, inject an `OSError` in the PV Store save during unload. The unload raises after platform removal. Grid remains open, the listener still serves, and the original adapter replies to Heartbeat. A subsequent runtime can be unable to bind that port. PV teardown itself has begun, leaving partial ownership that affects both profiles and reconnect.

**Correction required.** Ensure each owned cleanup runs even if an earlier save or close fails. Preserve and report the storage error while closing the adapter/listener and fencing remaining control work. Reuse the existing close paths and journal semantics. Test unload, HA Stop and failed setup with an injected final write error, a pending OCPP result and a new runtime binding the same local port. Verify all old owners and timers are drained.

### R3 · P1 · An observed permission gap can span PV accounting and restart eligibility

**Confirmed defect and stable blocker.** PV-ECO-04/05/07 exclude known ineligible time from import accounting and the strictly greater than 15-second reset. The permission watch invokes PV lifecycle, but its interruption branch checks Grid eligibility, which omits permission. A tick while disabled breaks the interval. If an accepted disable/enable pair arrives between eligible samples, neither callback breaks the previous economic endpoint. [PV lifecycle](../../custom_components/wallbox_manager/pv.py#L269) · [Tick permission check](../../custom_components/wallbox_manager/pv.py#L647) · [Budget sample](../../custom_components/wallbox_manager/pv_economics.py#L89) · [Grid eligibility](../../custom_components/wallbox_manager/grid.py#L756)

**Evidence.** With an eligible 1800 W import sample at 1000, observe permission false at 1001 and true at 1004. A tick at 1005 accrued 2.5 Wh across the whole five seconds, including the three seconds known disabled. In a separate run with a saved 50 Wh STOP and qualifying battery-charge input, low import began at 1000, permission was disabled at 1004 and restored at 1015, and the 1016 tick reset the budget and sent 1p/6 A. The simulated Accepted cleared the STOP with only one second of continuously eligible evidence after re-enable. A genuine disconnect does interrupt Grid eligibility and the PV sampling endpoints. The behavior affects the shared PV budget, including battery-free SURPLUS. It does not change the NETZ window.

**Correction required.** Interrupt only the existing economic interval endpoints when canonical permission becomes false or unavailable. Keep accumulated Wh, economic STOP and any previously qualified reset evidence under existing rules. No new clock, source expiry, physical check or dispatch. Add fake-clock tests for OFF→ON between ticks, interrupted low-import reset, and stable same-generation input with no actual permission edge.

### R4 · P2 · Terminal transaction IDs accumulate across reconnect and restart

**Confirmed growth.** WBM-ARCH-12 favors a minimal store. Terminal and superseded IDs enter `closed_transactions`, survive every generation reset and serialize as a sorted full list in the current session document. Load restores that list. Duplicate/late terminal identity fencing is legitimate, but the structure grows for the lifetime of the installation. [Session admission and retirement](../../custom_components/wallbox_manager/session.py#L67) · [Schema-2 load and save](../../custom_components/wallbox_manager/session.py#L279)

**Evidence and impact.** A pure replay of 4,096 sequential transactions across 128 reconnect generations retained all 4,096 IDs in memory and in the schema-2 document. This affects the shared NETZ/PV session Store write size and startup cost. No material latency at ordinary household scale was measured. This is a follow-up, outside the stable blockers above.

**Correction.** If long-lived growth warrants a change, first establish a defensible Stationary replay horizon or use an existing monotonic causal boundary to retain the needed suppression without keeping every terminal ID forever. Add long-running generation/reload and old-ID replay tests, and measure file/write cost. An arbitrary purge could allow a previously retired transaction to become live.

### I1 · Informational · Full observation recovery depends on valid Stationary evidence

**Unverified interface limitation.** WBM-ARCH-05–08/12 and PV-ARCH-09 require individual generation initialization and truthful degradation. The source supports registration snapshots or first changed reports, but scope, source timestamps and missing samples can delay some values indefinitely. An old economic scope with a different transaction ID and no matching Ended also remains inhibited. Evidence comes from the startup matrix and current-journal tests. No extra WBM polling or inferred fallback is justified. Establish completeness and acceptable recovery behavior in operator commissioning. ## Operator acceptance before stable release

These are **physical operator acceptance** items. The audit used simulated peers and local source only.

1. Verify the F2 listener boundary from trusted LAN, the authenticated VPN and an outside/untrusted network. Verify station routing and reachability after HA restart. Keep the station listener off the public Internet.
2. Capture one real initial/reconnect trace after HA restart, Stationary process restart and network interruption, with same and different transactions. Confirm the configured authority, permission, connector status, phase, capabilities, current/voltage/power, valid zero channels and energy appear from actual evidence. Verify the UI exposes unavailable evidence distinctly and reports ACK separately from applied offer and measured consumption. Confirm acceptable recovery when Stationary has a different transaction and no matching Ended.
3. In a controlled session after R1 is corrected, exercise NETZ active, late start, expiry and offline Stop. Confirm the original deadlines, no blind resend on failed reconnect readback, ordinary mismatch correction and independently confirmed release-OFF 0 A when eligible. Check Stationary's treatment of phase/re-enable lockout.
4. After R2 and R3 corrections, validate current-format HA reload and Stop, one resumed PV cadence, no economic downtime backfill, retained STOP and legitimate restart only after continuously eligible evidence. Exercise FAST, BALANCE and battery-free SURPLUS where configured. Check command, Stationary offer and EV consumption separately. Test F5 on a Stationary-supported safe test signal, with an in-flight proposal and later ordinary decision.
5. If CPU/Recorder is a publication gate, compare normal idle, one reconnect and sustained reconnect churn with operator-defined thresholds. Record HA CPU, entity/Recorder changes and Stationary logs, rather than extrapolating from the unit suite.

**Release decision.** Fix R1, R2 and R3 on separately reviewed branches before stable publication. The operator still needs to accept the incomplete-evidence behavior in I1, commission the actual network and hardware paths, and decide whether the measured scale makes R4 a release concern. No P0 defect was reproduced.
