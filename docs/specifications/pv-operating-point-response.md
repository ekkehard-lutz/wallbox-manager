# Shared PV operating-point navigation and EV settling

**Decision record:** 25 October 2026, operator's FAST discussion with explicit applicability to **both FAST and BALANCE**. **Status:** agreed controller-direction details; two cross-policy edge cases explicitly OPEN pending clarification. Overall PV V3 remains DRAFT; documentation only.

IDs: PV-STEP-01–06, PV-RESP-01–08.

## Common operating points (FAST and BALANCE)

| ID | Requirement |
| --- | --- |
| **PV-STEP-01** | Both FAST and BALANCE use the **same** capability-driven legal operating-point model and technical current lattice as NETZ (WBM-GRID-31–39). Plan nominal power as `P_nominal_W = 230 V × phases × requested_A` without consuming live voltage measurements for requested-point identity. Retain actual measured EV power separately. Stationary remains sole physical/electrical safety authority. Only modes genuinely advertised and enabled via WBM current caps exist; 2p is optional when advertised, not assumed for Stationary. |
| **PV-STEP-02** | On **upward regulation**, use a **single next legal ampere/current step in the currently confirmed positive phase mode** every **third eligible configured PV regulation cycle at most**. Exhaust that phase series to its allowed maximum **before** switching to the nearest strictly higher legal nominal point on another enabled series. A globally closer point in another overlapping phase mode must not cause an earlier switch. |
| **PV-STEP-03** | On **downward regulation**, stay in the currently confirmed positive phase mode for as long as an appropriate lower point exists there, even when a numerically closer point exists in an overlapping phase mode. When that phase series is exhausted at its minimum, change to the nearest strictly lower feasible point in another enabled series only if the desired lower power actually justifies leaving the current minimum. Large genuine reductions **may skip multiple current steps within the existing phase series in one regulation decision**, rather than spending a full cycle per 1 A, but must not use alternate overlapping phases for a finer approximation. If no positive point is economically warranted, the shared STOP/0 A policy applies. |
| **PV-STEP-04** | Illustrative Stationary ranges with 230 V planning, minimum 6 A, 1p cap 20 A, 3p cap 27 A: in 3p, 6 A is **4,140 W** and 7 A is **4,830 W**; disregard 1p/19 A **4,370 W** and 1p/20 A **4,600 W** while regulating within 3p. From 3p/6 A, a mere ideal point between 3,910 and 4,140 W does **not** prompt a premature 1p switch; only a truly lower point of **1p/17 A = 3,910 W** or less justifies the cross-series step. Conversely, 1p/20 A 4,600 W upward goes to 3p/7 A 4,830 W, not the lower 3p/6 A. These are examples, not hardcoded bounds or assumed 2p support. |
| **PV-STEP-05** | The common phase-first navigation semantics should **reuse** the existing tested NETZ technical model / `Envelope.navigate()` concepts, not be independently reproduced in FAST, BALANCE, or Lovelace. If a numerical power target is resolved via a different solver interface, it must still observe the **phase-first** precedence. Report the distinct **desired**, **requested**, **OCPP accepted**, **reported applied**, and **actually consumed** quantities faithfully. Phase-switch lockouts/rejection/recognized retry policy and owner protections remain separate from step selection. |
| **PV-STEP-06** | Interpret **three ticks** as three configured, eligible PV regulation cycles measured relative to the previous upward change; for the current default 5 s interval this is nominally **15 s**, not a fixed new wall-clock 15 s constant. Never queue several successive upward points while one current/phase change remains unresolved. A downward correction is not limited to every third tick. Inactive/no-authority/passive operation creates no background ramp; a disconnect does not authorize phantom applied points. Exactly when the 3-tick counter starts relative to asynchronous OCPP acceptance/confirmation must preserve the guarded execution boundary and be tested; it is not a per-measurement-generation gate. |

## Shared EV consumption and settling (FAST and BALANCE)

| ID | Requirement |
| --- | --- |
| **PV-RESP-01** | For any requested positive point, calculate offered **nominal** power from `230 V × number_of_phases × requested_current_A`. Compare with **actual total measured EV charging power** from WBM's canonical OCPP observations. The decision threshold is **at least 50%** of this nominal requested point: `P_EV_measured >= 0.5 × P_requested_nominal`. Do not use measured grid voltage to redefine the threshold; do not equate OCPP Accepted or reported amperes with consumed EV power. A valid 0 W is different from unknown/unavailable. The threshold is inapplicable to a requested 0 A point. |
| **PV-RESP-02** | **Upward adjustment is prohibited** while the vehicle consumes **less than 50%** of the currently offered nominal power, whether caused by initial EV startup, a temporary plug-release/unlock interval (~30 s), cell balancing or any other underconsumption. Upward adjustment may resume after actual consumption again reaches the threshold and the shared 3-tick/one-outstanding-change rules permit it. A vehicle drawing less than offered power must never be interpreted as spare energy that justifies repeatedly raising the request. |
| **PV-RESP-03** | **Starting from 0 A is exceptional:** after a genuinely requested and executable `0 A → positive` transition, hold the initially selected positive operating point for **10 configured eligible regulation cycles** with **no ordinary downward re-optimization**, even if the measured 50% threshold is reached earlier. This is a deliberately tolerated uncertain EV startup response, not an OCPP retry timer or a guaranteed physical charging start. Count active cycles of the same control context; do not manufacture elapsed cycles while permission, intent or command execution was never established. If the vehicle has not reached 50% after these 10 cycles, normal downward optimization may proceed on subsequent ticks, including down to 0 A where separately legitimate; upward optimization remains barred until 50% is measured. The user's exact phrase 'ten cycles in every case' governs **ordinary startup-down regulation**. |
| **PV-RESP-04** | During the initial 10-cycle startup hold, no ordinary *automatic point adjustment* is assumed. The shared three-tick upward cadence and 50% condition remain prerequisites afterward. **Whether upward may begin earlier than the full ten ticks once 50% is already observed is still an explicit clarification item**, because the user specified both mandatory ten-cycle startup waiting and a 50%-gated upward direction; do not invent a definitive exception yet. |
| **PV-RESP-05** | **During ongoing charging with an already positive requested point**, the same 50% gate prevents further upward regulation after the EV temporarily reduces its demand (e.g. vehicle unlocked for unplugging or cell balancing). **Downward** optimization remains permitted **immediately** when the current economic/SoC/grid conditions require it; it must not wait for the EV to resume consumption. A temporarily measured 0 W while a positive point remains selected is **not** a new `0 A → positive` startup and does not reset the 10-cycle hold. |
| **PV-RESP-06** | The startup ten-cycle and EV-underconsumption controls are **optimization delay**, not Stationary safety rules or a new authority/transaction/manager-release permission. Explicit operator **Stop**, actual profile switch, confirmed loss of Remote authority, mandatory SoC STOP and valid independent lifecycle/permission invalidation remain effective and must not be blocked for 10 ticks. These are **not** ordinary FAST/BALANCE downward fine-tuning. If conditions turn illegal for continued charging, do not hold the positive proposal merely to finish startup settling. |
| **PV-RESP-07** | Preserve the 50 Wh measured-grid-import accounting/STOP contract independently of settling timers. **OPEN CROSS-POLICY CHOICE:** if its existing nominal 50 Wh threshold is reached *inside the first 10 startup cycles*, should economic OFF override the startup hold? In the absence of explicit new authorization to weaken PV-ECO-01–09, the existing economic STOP has normative precedence; do **not** silently suppress it. The user should confirm this exception before implementing active PV. |
| **PV-RESP-08** | Acceptance: test 0→1p/6 A startup with 0%, 49.9%, exactly 50% and >50% measured nominal power, at ticks 1, 3, 9, 10 and 11. Verify ordinary downward hold for the full 10-cycle window and bounded downward release afterward; upward gating at 50% and three cycles; no artificial start from EV measured 0 W during an already positive offered 3p point. Simulate 30 s unlock charging drop and cell balancing underconsumption: no repeated upward steps, prompt justified downward decisions. Test an urgent operator STOP, SoC STOP and authority loss during startup: never delayed. Add phase-first 3p/6 A→1p/17 A and 1p/20 A→3p/7 A, 2p when advertised, disabled mode/current caps, large downward multi-step and phase-lockout reactions. Include exactly one relevant Level-2 log for each *changed* ramp/settling decision and none per held tick; see PV-DIAG-01–10. |

## Meaning of deadband / Totzone (not yet decided)

A **grid deadband**, e.g. the *illustrative* interval −100 W..+100 W around zero net exchange, means very small positive/negative exchange does not by itself provoke a downward reversal or unnecessary corrective setpoint; it is **not** an additional battery reserve, hardware limit or substitute for the 50 Wh import policy. The user has not accepted a particular value or even that a separately configured band is necessary. Quantized 1 A steps (230 W at 1p; 690 W at 3p), three-cycle upward cadence and measured-consumption gate already damp movement. Keep the band **OPEN** and test with/without a small band rather than choosing 100/200 W without evidence. A deadband must **not** prevent scheduled bounded FAST exploration at zero grid exchange; otherwise the old stuck-at-low-current behavior returns.

| WBM-GRID-31–39, backend `grid_point.Envelope.navigate()` | Reuse phase-first technical **series** navigation, allowed modes/limits and nominal 230 V points. No universal nearest-watt phase switching; no new frontend solver. |
| PV-FAST-01/03/04 | Adopt three-tick upward cadence and 50%-consumption test; replace historical all-source generation lock for every increase. Preserve one outstanding action and legitimate immediate economic reduction after startup. |
| PV-BAL-01–03 | The same ramp rate, technical navigation, startup exception and consumed-power gate apply to BALANCE, not a separate BALANCE increase policy. The later SoC target-recovery design remains separate and OPEN. |
| PV-SOC-01–03 | Shared SoC matrix unchanged. Mandatory independent SoC policy STOP is not disabled by settling. |
| PV-ARCH-05–09, WBM-ARCH-01–12 | One clocked PV decision from held valid observations; no new sensor TTL, regulator loop, station safety system or duplicate per-event control pass. |
| PV-ECO-01–09 | The economic STOP (50 Wh nominal import) and restart provenance are not implicitly relaxed. Specific startup/economic STOP conflict needs the separately noted user decision; no silent rule deletion. |
| WBM-PV-RELEASE-01–07 | The manager Start/Stop gate and independent 0 A pause remain unchanged. |
| PV-DIAG-01–10 | Log changed requested phase/current/SoC modes and relevant decision reason, including the 50%/10-tick settling **transition** when decision-driving; never log each identical tick. |

**Scope:** This document establishes the shared FAST/BALANCE operating-point and response design. It does not complete the separate BALANCE SoC/recharge law or the non-D economic restart design, and it authorizes **no** code/release/deployment change.
