# NETZ / Grid fixed operating point — successor requirements

**Decision:** 23 October 2026. **Status:** APPROVED target for the next NETZ implementation; **documentation only at this stage**. No code change, merge, release, or deployment is authorized here. IDs: **WBM-GRID-01–16**.

This document supersedes the NETZ-specific *implementation approach* in the historical [v0.3.2-beta.18 Grid design](https://github.com/ekkehard-lutz/wallbox-manager/blob/v0.3.2-beta.18/docs/grid-profile.md), especially 5% phase retention, post-command vehicle-current/phase optimization, and periodic retry of an already confirmed operating point. Retain its battery-reserve ownership, scheduling and profile settings where not expressly changed below. It is the narrowly approved NETZ successor to V04-07 and WBM-CTRL-12; passive v0.4 and the wider PV V3 draft remain historical/otherwise unchanged. [WBM-ARCH-01–12](architecture-responsibility.md) have precedence for physical safety, last-value-held observations, and requested/confirmed distinctions.

## Fixed profile behavior

| ID | Approved requirement |
| --- | --- |
| WBM-GRID-01 | NETZ is an event-driven **fixed-power profile**, not a regulator. WBM stores a requested power (kW; existing `soll_power`, default 11 kW), resolves the offered phase/current point and sends it once through guarded OCPP 2.1 `SetChargingProfile` for the appropriate active transaction. A confirmed unchanged operating point is never resent periodically. No PV/Fronius/BYD data is required to calculate its electrical point. |
| WBM-GRID-02 | Preserve explicit Remote takeover and independent `ChargingEnabled` authority/permission semantics. Profile selection or editing alone never takes control. A positive/zero `TxProfile` requires the existing valid connected-vehicle transaction; general permission ON can precede a vehicle or transaction. Do not silently substitute a nonexistent positive OCPP profile. |
| WBM-GRID-03 | On a new requested power, authorized start, applicable new transaction or genuinely unconfirmed/mismatched point, calculate from advertised supported phase modes, configured current minimum/step and two maximum current capabilities, installation caps and available electrical observations. The station alone validates hardware/current/phase safety. Requested, accepted, physically confirmed offered and measured vehicle power remain distinct; OCPP Accepted alone is not measured charge. No extra per-command hardware freshness proof. |
| WBM-GRID-04 | The supported modes are supplied by `SupportedPhaseModes`; a mode disabled locally through its allowed-current cap of zero is excluded completely. No unsupported phase mode may be selected, submitted or presented as configurable. For the installed Stationary device the modes are **1p and 3p**, never 2p. Mode-selection calculations may use nominal 230 V per phase for the user-defined phase threshold and must respect the actual whole-ampere executable grid and available voltage evidence when resolving the final offered point. |
| WBM-GRID-05 | **First positive start, or no confirmed ongoing positive point:** with 1p and 3p both enabled and 2p not eligible, use the requested boundary policy in their overlap: `P_boundary=(P_1p_max+P_3p_min)/2`. For the installed 230 V, 6 A minimum, 1p 20 A and 3p 27 A: 1p range **1,380–4,600 W**, 3p range **4,140–18,630 W**, so `P_boundary=4,370 W`. Choose 1p for requested power **<=4,370 W** and 3p above; within the chosen mode choose the closest admissible whole-ampere point subject to the selected approximation direction and caps. This is an explicit nominal phase-choice rule; because of 1 A quantization it does **not** promise a global minimum absolute error over both modes near the boundary. If no overlap or a mode is disabled, choose a technically permitted best candidate rather than inventing a phase or exceeding limits. If 2p is actually supported and enabled in a future station, include its **2,760–9,200 W** nominal 6–20 A range in generalized candidate comparison with deterministic low-phase-count tie breaking; never expose it on the current station. |
| WBM-GRID-06 | **Already running, confirmed positive offered point:** retain the physically confirmed current phase count whenever the newly requested power lies inside that mode's full available positive power range (considering configured phase cap, station limits, minimum and available voltage), **even if another phase count would approximate it more closely**. Select the nearest admissible current on that same phase mode. Request a physical phase change only if the new requested power is **below its minimum or above its maximum**, or the mode is explicitly disabled/unavailable. Do not infer physical phases from requested phase or mere elapsed time. A confirmed positive offer remains eligible for retention across temporary zero measured vehicle consumption; a confirmed 0 A/OFF point is not an ongoing positive point. |
| WBM-GRID-07 | Retire the user setting/entity `phase_switch_deviation_pct` (old default 5%) as an **active control setting**; no phase-switch tolerance/hysteresis based on percentage remains. Preserve unrelated settings/store fields for safe migration if needed, but do not continue showing this obsolete editor or allow it to affect point selection. The overlap and phase-range rules above replace it. |
| WBM-GRID-08 | `allowed_current_1p`, `allowed_current_2p`, `allowed_current_3p` (German: `Zulässiger Strom 1p/2p/3p`) are per-connector **integer ampere** settings. Each accepts **0** (disables the mode) or a whole-ampere value in the station's advertised inclusive `[MinimumCurrent, effective_max(mode)]` range. Reject non-integers and intermediate positive values below minimum. No mode can exceed the station's effective limits. If a legacy setting is absent, default to that mode's advertised effective maximum; a stored explicit 0 must stay 0. Invalid legacy fractional/out-of-range values require explicit safe migration/normalization with diagnostic, not a silent increase or disabling of a different mode. If all supported modes have cap 0, no positive NETZ point is executable; report unavailability without sending a command. |
| WBM-GRID-09 | Show an allowed-current editor **only** for a station-advertised supported phase mode; no 2p entity/editor for Wallbox01. The station advertises exactly **two numeric maximum-current capabilities** for a three-phase supply: maximum wallbox/per-phase current and maximum asymmetrical-load current. The latter applies to **both 1p and 2p**, subject also to the overall maximum. The existing OCPP fields `MaximumCurrent3Phase` (overall maximum, currently 27 A) and `MaximumCurrent1Phase` (asymmetry limit, currently 20 A) can carry these two values without adding a third 2p maximum variable. `MinimumCurrent`, `CurrentStep`, `SupportedPhaseModes`, etc. remain independent non-maximum capabilities. |
| WBM-GRID-10 | Keep the existing `power_approximation` policy (DOWN/NEAREST/UP) for whole-ampere resolution, with the phase-retention/start-mode precedence above. Never violate a station/installation hard current bound to honor approximation preference. Explicit zero requested power is a zero-current OCPP pause, **not** `ChargingEnabled=false`; observe the Stationary re-enable lockout on a subsequent positive point. A power edit uses the former **1-second trailing-edge debounce**; only the last pending target may be dispatched. |
| WBM-GRID-11 | **Recognized phase-switch or charging-reenable lockout:** keep the original desired point unresolved; do not report it applied. Stationary refuses the whole unsafe request atomically. When a valid station-specific remaining lockout value is included, schedule exactly the next attempt at **reported remaining seconds + 5 s**. Otherwise retry the **same current desired intent every 60 s** while the profile remains eligible. No PV/measurement regulatory tick or precomputed command queue is needed. Reevaluate the current phase/capabilities and live intent at dispatch; an already accepted substitute is not the desired point and is not mistaken for final completion. |
| WBM-GRID-12 | Only uniquely recognized `PhaseSwitchLockout` or `ChargingReenableLockout` responses authorize a timer retry. General `Rejected`, communication failures, generic `busy`, missing authority, unsupported hardware or ambiguous error messages must **not** start an indefinite retry. Existing older Stationary returns a generic rejection for charging-reenable lockout; the enhanced Stationary reason contract in [WB-GRID](https://github.com/ekkehard-lutz/wallbox-stationary/blob/develop/docs/specifications/grid-profile.md) must be implemented before promising automatic timed retries for that case. A safe positive substitute on the current phase mode may be applied on a confirmed phase lockout if it respects the approximation policy, all bounds and user authorization; otherwise retain the already confirmed point or report pending without a fabricated success. |
| WBM-GRID-13 | On success (supported OCPP confirmation/readback and proper generation), stop retry scheduling and **do not resend** the same point just because measured current, vehicle phase usage, SoC, telemetry or time changes. Delete the v0.3.2 60-second measured-phase response / promote-demote optimizer and percentage-based phase-switch avoidance. A genuine new desired power, profile, current-cap configuration or newly eligible transaction creates a new decision. Editing a setting, OFF, Local transition, connection/boot/authority generation change, profile switch or unload supersedes obsolete pending timers; no stale late command may escape its fence. On a reconnect, first reconcile supported actual point and Stationary recovery; reconnect alone never authorizes unconditional replay of an unchanged confirmed target. |
| WBM-GRID-14 | Preserve optional one-shot `grid_start_delay` and `grid_duration` scheduling, including explicit 00:00 immediate duration expiry, finite end time and charging-permission OFF at expiration; do not implement a periodic energy/power regulation cycle. Scheduling must respect explicit operator OFF and non-retroactive ownership semantics. |
| WBM-GRID-15 | Preserve the historical NETZ home-battery **temporary discharge-reserve** lifecycle, entirely separate from OCPP point selection. The per-connector `min_soc` remains the requested Grid reserve; central listener `min_soc_speicher` and `soc_speicher_aktuell` reference the writable reserve and measured storage SoC. Only a confirmed active NETZ session actually drawing energy may request the override. Save the original reserve durably before changing it. With configured reserve `R_grid`, storage SoC `S`, and original reserve `R_original`, request `max(R_original, floor_to_number_step(min(R_grid,S)))`, respecting number bounds and never lowering the original. Example 20/40/65 -> 40%; at SoC 37.8% and 1% step -> 37%. Observe HA state changes, write only on real change, confirm through the existing `number.set_value`/readback contract; no cycling/repeated writes. Restore only while the value is still WBM-owned and not externally changed; preserve journal/recovery over HA reload, restore on actual charging end/permission OFF/profile/owner/authority changes. Missing/invalid mappings disable only battery override, **never fixed NETZ power**; changing SoC/reserve alone never resends OCPP current/phase. |
| WBM-GRID-16 | Acceptance: startup choices at/below/above 4,370 W, discrete 1 A counterexamples, live positive 1p/3p retention in overlap and mode switch outside range, disabled 3p=0 with 2p unavailable, integer-only limits and missing legacy values, two-max-capability semantics, exact lockout reasons, +5 s versus 60 s next-attempt deadlines, obsolete timer fencing, station zero-current restart behavior, no repeat after confirmed point, reserve override/persistence/restoration, timing, transaction and OCPP authority semantics. Distinguish simulated software tests from real hardware acceptance. |

## Examples and source distinction

At 230 V and supported modes (1, 3), the installed station advertises `MinimumCurrent=6`, `MaximumCurrent3Phase=27`, `MaximumCurrent1Phase=20`, `CurrentStep=1`. Configured 3p cap **0** leaves only 1p; **never** switch phases. A positive 3p point remains 3p for a later power request anywhere in its admissible 3p range, including the overlap where 1p might be a closer approximation.

**Comparison note (non-normative):** openWB documents a minimum five-minute buffer between automatic phase switches (typical 7–15 minutes); the go-e API publishes minimum phase-toggle wait and minimum phase-wish timing keys and a reason for minimum charging pause. Such firmware behavior is not a WBM safety substitute. See [openWB](https://wiki.openwb.de/doku.php?id=openwb%3Avc%3A2.1.9%3Asoftware%3Aeinstell-konfig%3Aladeeinstellungen%3Auebergreifendes%3Aallgemein) and [go-e API](https://github.com/goecharger/go-eCharger-API-v2/blob/main/API_KEYS_FIRMWARE/apikeys-de.md).

No production implementation is claimed by this specification.
