# NETZ / Grid fixed operating point — successor requirements

**Decision:** 23 October 2026. **Status:** APPROVED target for the next NETZ implementation; **documentation only at this stage**. No code change, merge, release, or deployment is authorized here. IDs: **WBM-GRID-01–16**.

This document supersedes the NETZ-specific *implementation approach* in the historical [v0.3.2-beta.18 Grid design](https://github.com/ekkehard-lutz/wallbox-manager/blob/v0.3.2-beta.18/docs/grid-profile.md), especially 5% phase retention, post-command vehicle-current/phase optimization, and periodic retry of an already confirmed operating point. Retain its battery-reserve ownership, scheduling and profile settings where not expressly changed below. It is the narrowly approved NETZ successor to V04-07 and WBM-CTRL-12; passive v0.4 and the wider PV V3 draft remain historical/otherwise unchanged. [WBM-ARCH-01–12](architecture-responsibility.md) have precedence for physical safety, last-value-held observations, and requested/confirmed distinctions.

## Fixed profile behavior

| ID | Approved requirement |
| --- | --- |
| WBM-GRID-01 | NETZ is an event-driven **fixed-power profile**, not a regulator. WBM stores a requested power (kW; existing `soll_power`, default 11 kW), resolves the offered phase/current point and sends it once through guarded OCPP 2.1 `SetChargingProfile` for the appropriate active transaction. A confirmed unchanged operating point is never resent periodically. No PV/Fronius/BYD data is required to calculate its electrical point. |
| WBM-GRID-02 | Preserve explicit Remote takeover and independent `ChargingEnabled` authority/permission semantics. Profile selection or editing alone never takes control. A positive/zero `TxProfile` requires the existing valid connected-vehicle transaction; general permission ON can precede a vehicle or transaction. Do not silently substitute a nonexistent positive OCPP profile. |
| WBM-GRID-03 | On a new requested power, authorized start, applicable new transaction or genuinely unconfirmed/mismatched point, calculate **all** operating ranges from the live station diagnostic values `MinimumCurrent`, `MaximumCurrent` (maximum wallbox current), `MaximumAsymmetryCurrent` (maximum unbalanced/asymmetrical current), `CurrentStep`, advertised `SupportedPhaseModes`, and the WBM phase-specific user cap. The station alone validates hardware/current/phase safety. Requested, accepted, physically confirmed offered and measured vehicle power remain distinct; OCPP Accepted alone is not measured charge. No extra per-command hardware freshness proof. |
| WBM-GRID-04 | Define eligible modes as advertised `SupportedPhaseModes` intersected with the modes whose WBM `allowed_current_Np` is a valid **positive** integer cap meeting `MinimumCurrent` and not exceeding the mode's effective station maximum. A configured cap of **0 removes the mode entirely** from the phase selection, power-range calculation and UI choice: it is not treated as a zero-watt charging range (because `MinimumCurrent > 0`). Do not select, send or expose unsupported modes. The current Stationary advertises **(1,3)**, never 2p. Use a **consistent voltage basis** for all calculated phase power ranges and boundaries (valid observed per-phase voltages where available, otherwise documented nominal 230 V planning fallback); retain the station's final authority over electrically executable current/phase requests. No fixed wattage range or threshold is an invariant. |
| WBM-GRID-05 | **First positive start, or no confirmed ongoing positive point:** calculate **for each eligible mode n** its current envelope `[I_min, I_allowed_n]` and power envelope `[P_min(n), P_max(n)]` from the chosen voltage basis: with equal phase voltages `P_min(n) = n × V × MinimumCurrent` and `P_max(n) = n × V × allowed_current_np` (for unequal voltages use the sum of the applicable phase voltages). Sort only **eligible** phase counts ascending. For every pair of **successive eligible phase counts** `(n_low,n_high)`, compute their dynamic selection boundary `B = (P_max(n_low) + P_min(n_high)) / 2`. A requested power at the boundary belongs to the **lower** count; above it choose the higher count, applying successive boundaries where modes 1p/2p/3p are eligible. For the *illustrative current values* 230 V, 6 A min, allowed 1p=20 A and 3p=27 A, with 2p not available, ranges are **1,380–4,600 W** and **4,140–18,630 W**, giving **B=4,370 W**, **not** a hardcoded threshold. A cap change, new minimum, eligible-mode change or changed voltage basis recalculates it. For a genuinely supported/enabled 2p, calculate its range and adjacent boundaries using **its own** allowed-current cap; do not assume 20 A or a static 2p range. The 1-A grid and DOWN/NEAREST/UP policy apply *within* the selected feasible mode. If ranges are disjoint or multiple boundaries are non-monotonic, choose a deterministic executable candidate without inventing a mode or exceeding caps; document and test such configurations separately. Quantization can mean a different phase would be globally closer; the approved midpoint phase-selection rule takes precedence. |
| WBM-GRID-06 | **Already running, confirmed positive offered point:** retain the physically confirmed phase count whenever the newly requested power lies inside that mode's **dynamically calculated** `[P_min(n), P_max(n)]` interval from `MinimumCurrent`, the eligible mode's **own** positive integer allowed-current cap and the consistent voltage basis, **even if another eligible phase count would approximate more closely**. Resolve to an admissible current on that same mode. Request a phase change only if the new request falls outside that interval or the mode becomes disabled/unsupported. Do not infer physical phases from a requested phase or mere elapsed time. A confirmed positive offer remains eligible for retention across temporary zero measured vehicle consumption; confirmed 0 A/OFF is not an ongoing positive point. |
| WBM-GRID-07 | Retire the user setting/entity `phase_switch_deviation_pct` (old default 5%) as an **active control setting**; no phase-switch tolerance/hysteresis based on percentage remains. Preserve unrelated settings/store fields for safe migration if needed, but do not continue showing this obsolete editor or allow it to affect point selection. The overlap and phase-range rules above replace it. |
| WBM-GRID-08 | `allowed_current_1p`, `allowed_current_2p`, `allowed_current_3p` (German: `Zulässiger Strom 1p/2p/3p`) are per-connector **integer ampere** settings. Each accepts **0** (fully excludes the phase mode from all calculations and switching) or a whole-ampere value in `[MinimumCurrent, effective_max(mode)]`, inclusive. `effective_max(1p)=effective_max(2p)=min(MaximumCurrent,MaximumAsymmetryCurrent)` and `effective_max(3p)=MaximumCurrent`, also observing any additional station constraints. Never treat zero as a valid positive operating-current limit; for a disabled mode the minimum would exceed its allowed current, hence **no** `[P_min,P_max]` exists. Reject non-integers and positive values below minimum or above effective max. If a legacy setting is absent, default to that mode's advertised effective maximum; preserve an explicitly stored 0. Handle invalid legacy fractional/out-of-range values through explicit safe migration/diagnostics, never a silent increase. If all supported modes are disabled, no positive NETZ point is executable; report this and send no command. |
| WBM-GRID-09 | Show an allowed-current editor **only** for an actually advertised supported phase mode; **never** show 2p for Wallbox01. The new Stationary OCPP **diagnostic**, read-only Actual maximum-current variables are exactly **`MaximumCurrent`** (German **`Maximaler Strom`**, overall wallbox/per-phase maximum, e.g. 27 A) and **`MaximumAsymmetryCurrent`** (German **`Maximaler Strom Schieflast`**, max for both 1p and 2p, e.g. 20 A). They **replace** the misleading legacy device-model maximum variables `MaximumCurrent1Phase` and `MaximumCurrent3Phase`; no phase-specific maximum capability is advertised as part of the new contract. `MinimumCurrent`, `CurrentStep`, `SupportedPhaseModes` etc. continue as separate read-only diagnostics. WBM consumes the new names for its calculations; migration from the old wire inventory requires coordinated Stationary/WBM implementation and tests, never an assumed live deployed capability. User `allowed_current_Np` values remain WBM-side *configurable* caps, not Stationary diagnostics. |
| WBM-GRID-10 | Keep the existing `power_approximation` policy (DOWN/NEAREST/UP) for whole-ampere resolution, with the phase-retention/start-mode precedence above. Never violate a station/installation hard current bound to honor approximation preference. Explicit zero requested power is a zero-current OCPP pause, **not** `ChargingEnabled=false`; observe the Stationary re-enable lockout on a subsequent positive point. A power edit uses the former **1-second trailing-edge debounce**; only the last pending target may be dispatched. |
| WBM-GRID-11 | **Recognized phase-switch or charging-reenable lockout:** keep the original desired point unresolved; do not report it applied. Stationary refuses the whole unsafe request atomically. When a valid station-specific remaining lockout value is included, schedule exactly the next attempt at **reported remaining seconds + 5 s**. Otherwise retry the **same current desired intent every 60 s** while the profile remains eligible. No PV/measurement regulatory tick or precomputed command queue is needed. Reevaluate the current phase/capabilities and live intent at dispatch; an already accepted substitute is not the desired point and is not mistaken for final completion. |
| WBM-GRID-12 | Only uniquely recognized `PhaseSwitchLockout` or `ReenableLockout` responses authorize a timer retry. General `Rejected`, communication failures, generic `busy`, missing authority, unsupported hardware or ambiguous error messages must **not** start an indefinite retry. Existing older Stationary returns a generic rejection for charging-reenable lockout; the enhanced Stationary reason contract in [WB-GRID](https://github.com/ekkehard-lutz/wallbox-stationary/blob/docs/grid-profile-phase-policy/docs/specifications/grid-profile.md) must be implemented before promising automatic timed retries for that case. A safe positive substitute on the current phase mode may be applied on a confirmed phase lockout if it respects the approximation policy, all bounds and user authorization; otherwise retain the already confirmed point or report pending without a fabricated success. |
| WBM-GRID-13 | On success (supported OCPP confirmation/readback and proper generation), stop retry scheduling and **do not resend** the same point just because measured current, vehicle phase usage, SoC, telemetry or time changes. Delete the v0.3.2 60-second measured-phase response / promote-demote optimizer and percentage-based phase-switch avoidance. A genuine new desired power, profile, current-cap configuration or newly eligible transaction creates a new decision. Editing a setting, OFF, Local transition, connection/boot/authority generation change, profile switch or unload supersedes obsolete pending timers; no stale late command may escape its fence. On a reconnect, first reconcile supported actual point and Stationary recovery; reconnect alone never authorizes unconditional replay of an unchanged confirmed target. |
| WBM-GRID-14 | Preserve optional one-shot `grid_start_delay` and `grid_duration` scheduling, including explicit 00:00 immediate duration expiry, finite end time and charging-permission OFF at expiration; do not implement a periodic energy/power regulation cycle. Scheduling must respect explicit operator OFF and non-retroactive ownership semantics. |
| WBM-GRID-15 | Preserve the historical NETZ home-battery **temporary discharge-reserve** lifecycle, entirely separate from OCPP point selection. The per-connector `min_soc` remains the requested Grid reserve; central listener `min_soc_speicher` and `soc_speicher_aktuell` reference the writable reserve and measured storage SoC. Only a confirmed active NETZ session actually drawing energy may request the override. Save the original reserve durably before changing it. With configured reserve `R_grid`, storage SoC `S`, and original reserve `R_original`, request `max(R_original, floor_to_number_step(min(R_grid,S)))`, respecting number bounds and never lowering the original. Example 20/40/65 -> 40%; at SoC 37.8% and 1% step -> 37%. Observe HA state changes, write only on real change, confirm through the existing `number.set_value`/readback contract; no cycling/repeated writes. Restore only while the value is still WBM-owned and not externally changed; preserve journal/recovery over HA reload, restore on actual charging end/permission OFF/profile/owner/authority changes. Missing/invalid mappings disable only battery override, **never fixed NETZ power**; changing SoC/reserve alone never resends OCPP current/phase. |
| WBM-GRID-16 | Acceptance: compute **dynamic** power ranges and adjacent midpoint thresholds from varying `MinimumCurrent`, both **new** Stationary diagnostic maxima, per-mode `allowed_current_Np` caps, phase availability and voltage basis. Verify example B=4,370 W **only** for illustrative 6 A / 20 A 1p / 27 A 3p / 230 V values; vary 1p cap, 3p cap, min current, voltage, available modes and add/remove hypothetical 2p. Test disabled 3p=0 with 2p unavailable, 2p=0 excluded from adjacent-pair boundaries, integer-only limits, live positive mode retention in overlap/outside range, new OCPP variable names/inventory/readback and old-wire migration, exact lockout reasons and +5 s/60 s deadlines, stale timer fences, Stationary restart restoration, non-repetition after confirmation, battery reserve lifecycle, timing, transactions and authority semantics. Simulated tests are not physical acceptance. |

## Examples and source distinction

**Illustration, not invariant:** if Stationary reports `MinimumCurrent=6`, `MaximumCurrent=27`, `MaximumAsymmetryCurrent=20`, `CurrentStep=1`, `SupportedPhaseModes=(1,3)`, WBM configures `allowed_current_1p=20`, `allowed_current_3p=27`, and calculation uses 230 V, the eligible ranges are 1p **1,380–4,600 W**, 3p **4,140–18,630 W** and midpoint **(4,600+4,140)/2=4,370 W**. Changing *either allowed-current cap*, the diagnostic minimum, station maximum or relevant voltages recomputes the ranges/boundary; 3p cap **0** removes 3p, leaves only 1p and therefore leaves **no midpoint or reason to phase-switch**. An existing confirmed 3p point remains 3p when the new request lies in its freshly calculated valid 3p range even if 1p would approximate more closely.

**Comparison note (non-normative):** openWB documents a minimum five-minute buffer between automatic phase switches (typical 7–15 minutes); the go-e API publishes minimum phase-toggle wait and minimum phase-wish timing keys and a reason for minimum charging pause. Such firmware behavior is not a WBM safety substitute. See [openWB](https://wiki.openwb.de/doku.php?id=openwb%3Avc%3A2.1.9%3Asoftware%3Aeinstell-konfig%3Aladeeinstellungen%3Auebergreifendes%3Aallgemein) and [go-e API](https://github.com/goecharger/go-eCharger-API-v2/blob/main/API_KEYS_FIRMWARE/apikeys-de.md).

No production implementation is claimed by this specification.


## Amendment — zero-current quantization and lockout fallbacks (23 October 2026)

The following approved requirements **WBM-GRID-17–21** clarify and supersede
WBM-GRID-05/06/10–13 wherever older wording implied that every positive
requested power must be rounded up to a positive minimum-current point.
No Stationary protocol change is required for this amendment.

| ID | Requirement |
| --- | --- |
| WBM-GRID-17 | **0 A is an executable, true candidate** whenever the requested power cannot be met on a supported positive-current step. DOWN (Nicht über Soll) chooses the greatest allowed offered power **not exceeding** the requested power, including 0 A. UP (Nicht unter Soll) chooses the smallest positive allowed offer **not below** a positive request; any strictly positive request below the minimum immediately chooses the positive minimum. NEAREST (Nächster Wert) chooses the smallest absolute difference among zero and positive whole-step candidates, with ties at a positive/zero boundary resolved toward the positive offer. A **0 W request always means 0 A** under all directions. For an impossible upper/lower bound at physical maxima, clamp to an executable limit and show the limitation rather than claiming that the direction's inequality can be met. |
| WBM-GRID-18 | Each positive whole-ampere offering and 0 A must be evaluated against the **actual configured minimum and step**, applicable mode, allowed-current caps and consistent voltage basis. At illustrative 230 V and 1p minimum 6 A, DOWN offers 0 A below 1,380 W; 6 A from 1,380 W, 7 A from 1,610 W. UP offers 6 A for every positive request through 1,380 W and 7 A above 1,380 W. NEAREST uses the zero/6 A midpoint 690 W and the 6/7 A midpoint 1,495 W (the card's 0.1-kW setpoint increments mean first transitions at 0.7 and 1.5 kW respectively). These thresholds are illustrative calculations, **never constants**. |
| WBM-GRID-19 | When the desired new phase is **temporarily blocked by Stationary PhaseSwitchLockout**, compute a **single interim offer** on the *physically confirmed current phase mode*, using the same direction-aware nearest permitted current (including 0 A). An interim point may deliberately diverge from the nominal desired point but must respect station limits, allowed-current mode caps, and direction policy. If the present mode is disabled/unsupported by WBM, only an interim **0 A** may be sent. A successfully confirmed interim point is displayed as **actual**, never treated as fulfillment of the original desired different-phase point. If the interim point is already applied, do not resend it. |
| WBM-GRID-20 | Keep the desired new-phase request outstanding and retry after Stationary's remaining lockout plus 5 s or after 60 s when no valid remaining duration was supplied. If a temporarily applied 0 A starts a Stationary re-enable lockout, handle its distinct ReenableLockout in exactly the same way; do not bypass or preempt physical Stationary timers. Every retry recalculates the current desired point against the latest valid observation and generation. Cancel stale retries on explicit operator OFF, authority/transaction change, profile change and new intent. If an interim dispatch is independently rejected, retain truthful status; a new recognized remaining lockout may determine the next retry, but unrelated errors do not authorize uncontrolled retries. |
| WBM-GRID-21 | The WBM card's **Wallboxparameter** line contains only the concise physically confirmed actual phase/current and, **if different**, an arrow to the pending requested phase/current. German examples: `1-phasig 7A`, `3-phasig 0A → 1-phasig 6A`, `3-phasig 6A → 1-phasig 7A`. Show unknown actual as `—` rather than fabricating confirmation. Do not include voltages, individual phase currents, authority, confirmed-offer wattage or other diagnostics inside this line; existing Home Assistant entities and command-status diagnostics remain available elsewhere. |

### Boundaries and test matrix

Cover every mode offered (only 1p and 3p on the installed Stationary), 0 W
request, just below/at/above zero/minimum midpoint, exact minimum, adjacent
ampere midpoints, maximum, requests above maximum, changed voltage/current
limits, 0 A user-disabled phase counts, overlap/disjoint mode ranges, ongoing
phase retention, and each of DOWN/UP/NEAREST. For an active 3p station whose
desired 1p switch is blocked, at nominal 230 V: DOWN and 1.5 kW requires interim
**3p/0 A** before eventually 1p/6 A; UP and 1.4 kW requires interim **3p/6 A**
before eventually 1p/7 A. A subsequent ReenableLockout may delay the final
1p/6 A; never display the interim point as the completed goal. Test both
with simulated OCPP rejections/readbacks and explicitly record physical
acceptance as pending.

## Amendment — explicit SET for NETZ power and timing (23 October 2026)

| ID | Requirement |
| --- | --- |

Editing any of these in the card or directly through the existing HA Number/Text entities changes only the draft; no OCPP current/phase command, charging permission change, authority takeover or existing schedule alteration results. No implicit approval on field blur, Enter, time delay, repeated +/- steps, reload, reconnect or page refresh. Keep existing entity IDs and expose approved values to the control runtime. |
| WBM-GRID-23 | Add a dedicated per-connector HA **SET button entity**. | WBM-GRID-24 | Show **SET only for an unapproved meaningful difference**: (a) the drafted start delay or duration differs from the approved value (distinguish empty/unset from '00:00'), **or** (b) drafted power requires a different **executable phase/current target** than the last approved NETZ operating point, using the existing capability envelope, approximation and phase-retention policy. Compare to **approved desired**, NOT physical actual/confirmed (which may be different during lockouts). SET disappears after successful durable approval by WBM, **not** after OCPP confirmation; outstanding real phase/re-enable locks keep the normal actual → desired/status presentation but do not re-show SET. | WBM-GRID-27 | SET approves start delay and duration only as configuration for the **next applicable** permission/start event. Pressing SET during an existing charging session does not restart a delay, retroactively change an active duration deadline, interrupt charging or change charging permission. Draft timings have no effect on current or future schedule until approved. |
| WBM-GRID-28 | On upgrade from beta.10, initialize last approved values from the **existing active persisted NETZ values**, with drafts equal to those values. No surprise SET on upgrade, no changed OCPP point, no accidental schedule rearming. Persist both states across HA restart/reload without auto-approving unapproved drafts; preserve all existing entity IDs and unknown/foreign profile data. Multiple cards and direct HA service/automation edits must see the same authoritative draft, approved revision and SET-needed status. |
| WBM-GRID-29 | Render a genuine accessible **SET** control next to the NETZ power/time editors, driven by **backend-authoritative** pending/ready state and wired to the new HA button entity, not solely by local JavaScript. The button remains usable for durable approval regardless of offline/Local/unplugged status, provided the draft is valid; no OCPP authority is implicitly granted. Show errors and preserve pending edits on failures, suppress duplicate presses. Keep locale parsing, +/- long press, clear-time, focus behavior, multi-instance isolation, existing immediate reserve/approximation controls and concise Wallboxparameter actual → desired display. Displayed desired must reflect approved operating-point intent, not an unapproved draft. |
| WBM-GRID-30 | Regression matrix: repeated +/- and time editing sends **no interim OCPP**; SET visible for changed executable point or timing and hidden for equal point; button hides after approved durable SET even during lockout; no raw draft enters control on approximation change; equivalent numerically different power auto-approves with no OCPP; offline/Local/no-vehicle SET commits for later eligibility without takeover; beta.10 migration and HA restart preserve approved and draft separately; direct HA Number/Text edit, multiple cards, persistence failure/invalid inputs, concurrency and old-callback fencing do not bypass SET; no active duration rearming; reserve/approximation remain immediate; no regression in WBM-GRID-17–21, phase/re-enable retries or acknowledged/actual readback. ### Approval examples

- Approved 1p/6 A, drafted numeric power also resolves to 1p/6 A, timing unchanged: auto-save the new numeric power as approved; **no SET and no OCPP**.
- Approved 1p/6 A, draft resolves to 1p/7 A: **show SET**; retain the approved 1p/6 A request until pressed. After successful SET, hide button even if actual remains 1p/6 A due to lockout; distinguish actual → approved desired.
- Power point unchanged but start delay 00:05 or duration 02:00 drafted: **show SET**.
- Unapproved power draft present, then approximation changes: update/execute based on **previous approved numeric power only**. Do not sneak staged power into OCPP.
- Keep Stationary untouched. Merely deferring card JavaScript writes is not sufficient; the split must be central and survive HA entity/service access and restart.
